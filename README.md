# 筋トレノート（筋トレレビュー拡張）

Life Fitness / Advagym CSVとInBody CSVの可視化に、日々の記録を追加した静的PWAです。サーバーへの健康情報送信はありません。

## ローカル起動

```sh
npm run dev
```

http://127.0.0.1:4173/ を開きます。別のアプリが使っている場合は `PORT=4187 npm run dev` などで変更してください。初期設定はMac内のみ（127.0.0.1）で待ち受けます。今回は公開・本番デプロイは行っていません。

**保存領域はブラウザ・URLのオリジンごとに別です。** 以前使用したブラウザとURLで開いたときだけ、そのURLの既存データを移行できます。GitHub Pagesや別ポートの保存領域は自動では移りません。CSV再選択またはバックアップの復元が必要です。

## 使い方

- 固定下部ナビで「ホーム」「トレーニング履歴」「体組成」を切り替えます。ブラウザの戻る操作にも対応しています。
- ホームでジムと機材・メニューを追加します。既存CSVを読み込むと、そのCSVの種目を機材候補として使えます。
- 機材には表示名、ジム、部位、筋力/有酸素、負荷/補助重量、メーカー、正式機材名、写真、長文メモを登録できます。同じ種目の別ジム・別機材は個別に追加します。メーカー・正式名は空欄のままでも保存できます。
- 「トレーニングを記録」で機材を選び、重量kg・回数・休憩秒、または時間秒・距離m・kcalを入力します。自重の重量は0。前回のセットの参照とコピー、セットの追加・削除ができます。
- 入力途中は自動保存。確定は「記録を保存」です。カレンダーには保存した実績だけが載ります。未来日は保存できません。
- 最近の記録、またはカレンダーの日付から手入力の記録を展開して編集できます。編集中の下書きは、確定するまで過去の実績を変更しません。
- 機材のジムは追加時に記録へ保持します。ジム名称変更は同じIDを参照する過去記録にも反映します。機材を別ジムへ移しても過去の訪問場所は変わりません。
- ジム不明のCSV履歴は不明のまま。現在の機材設定から過去の場所を推測しません。1日に複数ジムの場合はカレンダーに複数色で表示します。
- 写真の選択・撮影はユーザー操作で開始します。最大20MBの画像を端末内で長辺1600pxのJPEGに変換して保存します。端末がHEICを読めない場合はJPEG/PNGを選んでください。

## データ保全とインポート

従来の `workout-review.csvText.v1` / `workout-review.inbodyCsvText.v1` などのlocalStorageキーは変更・削除しません。初回起動時に原文をIndexedDBの `workout-review-journal` へコピーします。以後、ジム・機材・写真・手入力・下書き・追加CSVはIndexedDBに保存します。保存完了前の入力はタブ専用のlocalStorage領域でも一時保全します。

CSVは置き換えず原文ごと追加します。同じ内容のファイルは追加せず、重なったトレーニング実績は日時・タイトル・全セット内容で重複排除します。手入力と同じ日のCSVは確認画面で追加する実績を選びます。除外した実績も元CSVに残ります。同じ日時のInBodyは先に取り込んだ測定を表示し、双方のCSV原文を保持します。

保存済み記録・機材の変更、CSV取り込み、復元の前には、IndexedDB内に旧状態のバックアップを同一トランザクションで保存します。容量不足などで保存が失敗した場合、元データを保持し、画面にエラーを表示します。別タブの変更を検知した場合は上書きしません。

「バックアップを書き出す」は写真・メモ・原文CSV・下書き・旧状態を含むJSONを端末へ保存します。健康情報を含むファイルなので自身で保管してください。「バックアップを復元」は新しいIDの項目を追加し、同じIDの現在の内容を上書きしません。同じIDの旧版を巻き戻す操作は未提供です。

ブラウザの保存領域消去・端末変更・プライベートブラウズによる消失には端末内バックアップだけでは対応できないため、必要に応じてJSONを書き出してください。クラウド同期はありません。

## 開発・検証

```sh
npm ci
npm run check
```

- `npm run lint`: ESLint（既存コード内の未使用グラフ関数4件は保持するため名前で除外）
- `npm run typecheck`: 新しい `src/journal-*.js` 3ファイルをTypeScriptのcheckJsで検査。既存の巨大なapp.js全体は型検査対象外。
- `npm test`: 21件。元CSVパーサー、重複、安定ID、カレンダー、入力検証、保存失敗・並行更新・バックアップなど。
- `npm run build`: 公開可能な静的ファイル10点のみ `dist/` に複製。個人CSV・写真・メモ・バックアップを含めません。ビルドはデプロイしません。

私有CSVをコピーせずに回帰検証する場合:

```sh
REAL_WORKOUT_CSV='/absolute/path/workout.csv' REAL_INBODY_CSV='/absolute/path/inbody.csv' npm test
```

個人データはGitに追加しないでください。`data/current.csv`、`data/*.private.csv`、`data/InBody*.csv`、`data/*Workout*.csv` は除外しています。元CSVからのメモ列は、Notes / Exercise note / Workout note / Memoの形式を保持します。生CSVは常に原文で保持され、Life Fitnessへのログインやメモ取得はしません。
